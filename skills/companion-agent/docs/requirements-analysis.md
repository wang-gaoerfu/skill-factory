## 三、用户旅程地图（User Journey Map）

### 3.1 场景一：孩子写作业遇到困难

```
══════════════════════════════════════════════════════════════════════
阶段1：遇到问题
══════════════════════════════════════════════════════════════════════

用户行为：
├── 看着作业本发呆
├── 皱眉、咬笔
├── 翻书找答案
└── 叹气

用户情绪：困惑 😕 → 焦虑 😰

用户想法："这道题我不会...怎么办..."

痛点：
├── 家长不在家/在忙
├── 不敢问家长（怕被说"这么简单都不会"）
└── 自己想不出来

机会点：
└── 智能体主动发现困难？（待定）

────────────────────────────────────────────────────────────────────

阶段2：求助智能体
────────────────────────────────────────────────────────────────────

用户行为：
├── 打开手机APP
├── 对智能体说："小萌，这道题怎么做？"
└── 拍照上传题目

用户情绪：期待 → 紧张

用户想法："希望能帮到我...不要批评我..."

智能体响应：
├── 识别题目
├── "这道题有点意思！我们一起来看看"
├── 不直接给答案，而是引导思考
└── "你还记得乘法要先算吗？"

关键体验：
├── ✅ 不批评、不评判
├── ✅ 引导式教学
└── ✅ 鼓励和耐心

────────────────────────────────────────────────────────────────────

阶段3：解决问题
────────────────────────────────────────────────────────────────────

用户行为：
├── 听讲解
├── 思考
├── "哦！我懂了！"
└── 继续做下一题

用户情绪：困惑 → 恍然大悟 😮 → 开心 😊

用户想法："原来是这样！我学会了！"

智能体响应：
├── "你真棒！"
├── 出一道类似的题验证
└── "看来你真的掌握了！"

关键体验：
├── ✅ 肯定孩子的努力
├── ✅ 验证理解
└── ✅ 记录掌握的知识点

────────────────────────────────────────────────────────────────────

阶段4：记录成长
────────────────────────────────────────────────────────────────────

智能体后台：
├── 记录：今天掌握了乘法优先级
├── 更新：数学知识点掌握情况
└── 生成：学习记录

家长端：
├── 收到推送："今天小明掌握了乘法优先级"
└── 可以查看详细学习报告

────────────────────────────────────────────────────────────────────

完整旅程图：

   遇到问题        求助智能体       解决问题        记录成长
       │               │               │               │
   😕 惊慌         😊 放心         😃 开心         😌 满足
       │               │               │               │
   ───────────────────────────────────────────────────────
       │               │               │               │
   痛点：          关键体验：       关键体验：      价值：
   家长不在        不批评、引导      肯定、验证      家长了解
   怕被批评        秒级响应          鼓励支持        孩子进步
```

### 3.2 场景二：孩子有心事想倾诉

```
══════════════════════════════════════════════════════════════════════
阶段1：遇到不开心的事
══════════════════════════════════════════════════════════════════════

用户行为：
├── 放学回家，情绪低落
├── 不想说话
├── 回房间关门
└── 发呆

用户情绪：难过 😢 → 委屈 😢

用户想法："今天同学说我矮...我很难过..."

痛点：
├── 不想跟家长说（怕家长担心或者说教）
├── 不知道跟谁说
└── 闷在心里很难受

────────────────────────────────────────────────────────────────────

阶段2：跟智能体倾诉
────────────────────────────────────────────────────────────────────

用户行为：
├── 打开手机，找智能体
├── "小萌，今天有人说我矮..."
└── 开始倾诉

用户情绪：难过 → 犹豫 → 想说

智能体响应：
├── "听起来你很难过，能告诉我更多吗？"（共情）
├── "同学说了什么让你这么在意？"（倾听）
└── "身高不是最重要的，你有很多优点呢"（安慰）

关键体验：
├── ✅ 不评判
├── ✅ 认真倾听
├── ✅ 共情和安慰
└── ✅ 引导正面思考

────────────────────────────────────────────────────────────────────

阶段3：情绪缓解
────────────────────────────────────────────────────────────────────

用户行为：
├── 继续倾诉
├── "其实我画画很好看"
├── 情绪好转
└── 开始聊别的

用户情绪：难过 😢 → 被理解 😌 → 开心 😊

用户想法："说出来舒服多了...小萌懂我..."

智能体响应：
├── "对呀！你画画真的很棒！"
├── "每个人都有自己的闪光点"
└── 记录：孩子在意身高、画画是特长

────────────────────────────────────────────────────────────────────

阶段4：家长收到动态
────────────────────────────────────────────────────────────────────

智能体后台：
├── 识别：情绪低落事件
├── 分析：因身高被同学说，需关注
└── 生成：情绪报告

家长端推送：
├── "今天小明情绪有些低落"
├── "原因：同学说他矮"
├── "建议：可以和孩子聊聊身高话题"
└── 完整报告可查看

家长行动：
├── 晚上主动关心孩子
├── 不直接提身高，而是夸孩子画画好
└── 孩子感受到家长的关心

────────────────────────────────────────────────────────────────────

完整旅程图：

   遇到不开心      跟智能体倾诉     情绪缓解        家长了解
       │               │               │               │
   😢 难过          😌 被理解        😊 开心         👨‍👩‍👧 连接
       │               │               │               │
   ───────────────────────────────────────────────────────
       │               │               │               │
   痛点：          关键体验：       关键体验：      价值：
   不敢跟家长说    不评判、倾听      共情、安慰      家长知道
   无人倾诉       秒级响应          正面引导        可以及时关心

   差异化价值：                                          ↓
   豆包没有家长端 → 家长不知道孩子发生了什么              家长参与
```

```
══════════════════════════════════════════════════════════════════════

══════════════════════════════════════════════════════════════════════

用户行为：
├── 工作一天，疲惫
├── 想知道孩子今天怎么样
├── 问孩子："今天怎么样？"
└── 孩子："还行。"（对话结束）

├── 孩子不愿意跟自己交流
├── 问什么都只说"还行"
└── 担心但无从了解

────────────────────────────────────────────────────────────────────

阶段2：打开家长端APP
────────────────────────────────────────────────────────────────────

用户行为：
├── 打开手机APP
```

## 四、功能优先级（MoSCoW分析）

### 4.1 优先级定义

| 级别 | 含义 | 说明 |
|------|------|------|
| **Must** | 必须有 | MVP必须包含，没有就不是产品 |
| **Should** | 应该有 | 重要但可以在后续版本 |
| **Could** | 可以有 | 加分项，时间允许再做 |
| **Won't** | MVP不做 | 暂时不考虑 |

## 五、需求验证清单

### 5.1 需要验证的问题

| 问题 | 验证方式 | 优先级 |
|------|----------|--------|
| 孩子是否愿意使用这个产品？ | 用户访谈、原型测试 | P0 |
| 家长是否愿意为"了解孩子"付费？ | 用户访谈、付费意愿调研 | P0 |
| 孩子是否信任AI陪伴？ | 用户访谈、心理研究 | P0 |
| 家长是否信任AI与孩子互动？ | 用户访谈、隐私调研 | P0 |
| 作业答疑是否足够准确？ | 技术测试 | P1 |
| 情绪识别是否足够准确？ | 技术测试 | P1 |

### 5.2 风险点

| 风险 | 影响 | 应对措施 |
|------|------|----------|
| 孩子不喜欢用 | 产品失败 | 充分测试，迭代优化 |
| 家长不信任AI | 付费率低 | 内容安全、隐私保护 |
| 内容不适合儿童 | 品牌危机 | 严格内容审核 |
| 孩子过度依赖 | 家长投诉 | 时长限制、健康提示 |
| 数据安全问题 | 信任危机 | 加密存储、合规设计 |
